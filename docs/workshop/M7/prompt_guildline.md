## ส่วน A: จัดทำเอกสารและตั้งค่า Repository (~20 นาที)

### A1 — สร้างเอกสารโปรเจกต์เบื้องต้น (`CLAUDE.md`)

**เป้าหมาย:** ให้ Claude อ่าน spec ของระบบแล้วสรุปออกมาเป็นไฟล์ `CLAUDE.md` ที่บอกว่าระบบนี้ทำอะไร เก็บข้อมูลไว้ที่ไหน และมีข้อห้ามอะไรบ้าง — **ห้ามมี API key หรือรหัสลับใด ๆ อยู่ในไฟล์นี้**

```
อ่านไฟล์ leaveeasy-spec.md ในโฟลเดอร์นี้ให้ครบ แล้วช่วยร่างไฟล์ CLAUDE.md
ให้มีหัวข้อ: ระบบนี้ทำอะไร, ชื่อ collection ทั้งหมดใน Firestore (users, leaveTypes,
leaveRequests, approvals), สถานะใบลา 3 ค่า (รอพิจารณา / อนุมัติ / ไม่อนุมัติ),
และกติกาว่าห้ามมี API key หรือรหัสลับใด ๆ ปรากฏในโค้ดหรือไฟล์นี้
ยังไม่ต้องเขียนโค้ด ขอดูแผนเนื้อหาก่อน
```

### A2 — ตั้งค่า `.gitignore` ให้ปลอดภัย

**เป้าหมาย:** กันไฟล์ที่มีความลับ (เช่นค่า config ของ Firebase, ไฟล์ `.env`) ไม่ให้หลุดขึ้น GitHub — **ต้องทำขั้นนี้ก่อน push ทุกครั้งเสมอ**

```
ช่วยตรวจดูโฟลเดอร์นี้ว่ามีไฟล์ไหนที่เป็นความลับ (API key, service account,
.env, ไฟล์ config ของ Firebase) แล้วช่วยสร้างหรือแก้ .gitignore ให้ครอบคลุมไฟล์เหล่านั้น
จากนั้นรัน git status ให้ดูว่าไฟล์ไหนจะถูก commit บ้าง ก่อนที่ผมจะ push ขึ้น GitHub
```

> ✅ **Checkpoint 1:** repo บน GitHub มีไฟล์ `CLAUDE.md` และ **ไม่มีไฟล์ credential ใด ๆ หลุดขึ้นไป**

## ส่วน B: ฟังก์ชัน CRUD หลัก (~40 นาที)

### B1 — เพิ่มใบลาใหม่ (Create)

**เป้าหมาย:** ให้ฟอร์มยื่นใบลาบันทึกข้อมูลจริงลง Firestore แทนข้อมูลปลอมที่ค้างในไฟล์

```
ช่วยทำให้หน้า new-leave-request.html บันทึกใบลาใหม่ลง Firestore จริง
เมื่อกดปุ่มบันทึก ให้สร้างไฟล์ใหม่ในโฟลเดอร์ leaveRequests โดยตั้งค่า status
เริ่มต้นเป็น "รอพิจารณา" เสมอ และมี createdAt ติดมาอัตโนมัติ
ก่อนบันทึกต้องตรวจว่าฟอร์มกรอกครบทุกช่องก่อน ถ้าครบแล้วให้กลับไปหน้ารายการ
ขอดูแผนก่อนว่าจะแก้ไฟล์ไหนบ้าง
```

### B2 — เปลี่ยนสถานะใบลา (Update)

**เป้าหมาย:** ให้ปุ่มอนุมัติ/ไม่อนุมัติแก้เฉพาะช่อง `status` โดยไม่กระทบช่องอื่น และกดซ้ำไม่ได้ถ้าพิจารณาไปแล้ว

```
ช่วยเพิ่มปุ่มอนุมัติและปุ่มไม่อนุมัติในหน้า leave-request-detail.html
กดแล้วให้แก้เฉพาะช่อง status ในไฟล์ leaveRequests เท่านั้น ห้ามเขียนทับช่องอื่น
ถ้าสถานะปัจจุบันไม่ใช่ "รอพิจารณา" ให้ปุ่มทั้งสองกดไม่ได้ (disabled)
ขอดูแผนก่อนว่าจะแก้ไฟล์ไหนบ้าง
```

### B3 — ลบใบลา (Delete)

**เป้าหมาย:** ลบใบลาได้ แต่ต้องมีหน้าต่างถามยืนยันก่อนเสมอ กดยกเลิกแล้วข้อมูลต้องไม่หาย

```
ช่วยเพิ่มปุ่มลบในหน้า leave-request-detail.html กดแล้วต้องมีหน้าต่างถามยืนยัน
ก่อนลบเสมอ ถ้ากดยืนยันจึงลบไฟล์ใน Firestore จริงแล้วพากลับหน้ารายการ
ถ้ากดยกเลิกให้ข้อมูลเดิมอยู่ครบเหมือนเดิม
```

### B4 — ทดสอบว่าข้อมูลไม่หายเมื่อปิดเบราว์เซอร์

**เป้าหมาย:** พิสูจน์ว่าข้อมูลเก็บอยู่ใน Firestore จริง ไม่ใช่ค้างในหน่วยความจำของเบราว์เซอร์

```
ช่วยเปิดเว็บนี้ให้ผมดูในเบราว์เซอร์หน่อย ผมจะลองกรอกใบลาใหม่ ปิดเบราว์เซอร์ทั้งหมด
แล้วเปิดใหม่เพื่อดูว่าใบลาที่กรอกไว้ยังอยู่ครบไหม
```

> ✅ **Checkpoint 2:** มีหลักฐาน (ภาพหน้าจอ) ว่าข้อมูลยังอยู่หลังปิด-เปิดเบราว์เซอร์ใหม่ และสามารถสร้าง แก้ไข ลบ ใบลาได้จริง

## ส่วน C: ระบบล็อกอินและสิทธิ์การเข้าถึง (~38 นาที)

### C1 — เปิดใช้ Firebase Authentication (Email/Password)

**เป้าหมาย:** เปิดใช้งานระบบล็อกอินแบบอีเมล/รหัสผ่านใน Firebase Console

```
ช่วยแนะนำทีละขั้นว่าต้องเข้า Firebase Console ไปเปิดใช้ Authentication
แบบ Email/Password อย่างไรบ้าง สำหรับโปรเจกต์นี้
```

### C2 — ทำหน้าสมัคร / ล็อกอิน / ล็อกเอาต์

**เป้าหมาย:** ผู้ใช้ต้องล็อกอินก่อนถึงจะใช้ระบบได้ และใบลาที่สร้างใหม่ต้องผูกกับผู้ใช้ที่ล็อกอินอยู่จริง (`requesterId` = uid ของผู้ใช้)

```
ช่วยทำหน้าสมัครสมาชิกและหน้าล็อกอินด้วย Firebase Authentication
สมัครสำเร็จแล้วให้สร้างไฟล์ใหม่ในโฟลเดอร์ users พร้อมช่อง role เริ่มต้นเป็น "employee"
เมื่อสร้างใบลาใหม่ ให้บันทึก requesterId เป็น uid ของผู้ใช้ที่ล็อกอินอยู่จริง
ถ้ายังไม่ได้ล็อกอิน ให้พาไปหน้าล็อกอินก่อนเสมอ พร้อมทำปุ่มล็อกเอาต์ด้วย
ขอดูแผนก่อนว่าจะแก้ไฟล์ไหนบ้าง
```

### C3 — เขียน ACL.md ร่วมกับ Claude (สิทธิ์ 3 บทบาท)

**เป้าหมาย:** ระบุชัดเจนว่าแต่ละบทบาททำอะไรได้/ไม่ได้บ้าง โดยเฉพาะ **ผู้ขอลาอนุมัติใบของตัวเองไม่ได้ และดูใบของคนอื่นไม่ได้**

```
ช่วยร่างไฟล์ ACL.md อธิบายสิทธิ์ของผู้ใช้ 3 บทบาทตาม leaveeasy-spec.md
คือ employee (ผู้ขอลา) manager (ผู้อนุมัติ) และ hr (ฝ่ายบุคคล)
ต้องระบุชัดว่า employee ยื่นใบลาได้ ดูใบของตัวเองได้ แต่ห้ามอนุมัติใบของตัวเอง
และห้ามดูใบลาของคนอื่น ส่วน manager และ hr ดูและอนุมัติได้ทุกใบ
```

### C4 — เขียน Firestore Security Rules ขั้นต่ำ + ทดสอบ

**เป้าหมาย:** ตั้งกฎขั้นต่ำ "ต้องล็อกอินก่อนถึงจะอ่าน/เขียนได้" แล้วพิสูจน์ว่าคนไม่ล็อกอินเข้าไม่ได้จริง

```
ช่วยเขียน Firestore Security Rules ขั้นต่ำให้ทุกโฟลเดอร์ (users, leaveTypes,
leaveRequests รวมถึงโฟลเดอร์ย่อย approvals) ต้องล็อกอินก่อนถึงจะอ่านหรือเขียนได้
เขียนเสร็จแล้วช่วยบอกวิธีทดสอบโดยเปิดหน้าต่างไม่ระบุตัวตน (incognito)
เพื่อดูว่าจะเจอ permission-denied จริงเมื่อยังไม่ได้ล็อกอิน
```

> ✅ **Checkpoint 3:** มีไฟล์ `ACL.md` ปุ่ม/เมนูแสดงตามสิทธิ์แต่ละบทบาทถูกต้อง และเปิดแบบไม่ล็อกอินแล้วเข้าไม่ได้จริง

## ส่วน D: นำระบบขึ้นใช้งานจริง (~20 นาที)

### D1 — Deploy ขึ้น Firebase Hosting (เว็บ + Security Rules)

**เป้าหมาย:** นำทั้งเว็บแอปและกฎเฝ้าข้อมูลขึ้น Firebase Hosting พร้อมกัน แล้วได้ลิงก์ `.web.app` มาใช้งานจริง

```
ช่วยแนะนำทีละขั้นตอนในการ deploy โปรเจกต์นี้ทั้งเว็บแอปและ Firestore security rules
ขึ้น Firebase Hosting พร้อมกัน แล้วบอกลิงก์ .web.app ที่ได้หลัง deploy สำเร็จ
```

### D2 — ทดสอบข้ามเครื่อง (ให้เพื่อนเปิดลิงก์)

**เป้าหมาย:** ยืนยันว่าคนอื่นเปิดลิงก์จากเครื่องอื่นได้จริง และต้องล็อกอินก่อนถึงจะเห็นข้อมูล

```
ผมจะส่งลิงก์ .web.app ที่ deploy แล้วให้เพื่อนลองเปิดจากเครื่องของเขา
ช่วยสรุปให้ว่าผมควรเช็กอะไรบ้างเพื่อยืนยันว่าเพื่อนเข้าได้จริง
และต้องล็อกอินก่อนถึงจะเห็นข้อมูล ไม่ใช่เห็นได้เลยทันที
```

> ✅ **Checkpoint 4:** เพื่อนเปิดลิงก์จริงของคุณได้ และเว็บบังคับให้ล็อกอินก่อนเห็นข้อมูล
https://leaveeasy-a17ab.web.app
