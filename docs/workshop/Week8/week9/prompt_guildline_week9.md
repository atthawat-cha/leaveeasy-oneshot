## เป้าหมายของสัปดาห์นี้

1. สร้าง LeaveEasy จากสเปคในรอบเดียว ด้วยผู้ช่วย AI **3 ตัว** ที่มีการจัดการโมเดลอย่างเหมาะสม
2. จัดหาผู้ช่วยที่ระบุโมเดลให้ตรงกับลักษณะงาน — **โมเดลเล็ก (haiku)** สำหรับงานทำตามแบบ, **โมเดลใหญ่ (sonnet)** สำหรับงานที่ต้องคิด
3. สร้างชุดทดสอบอัตโนมัติ **5 ตัวที่ผ่านทั้งหมด** ด้วย Playwright MCP รวมเทสต์ความปลอดภัย 2 ตัวเพื่อตรวจการรั่วไหลของข้อมูล
4. สร้างรายงานผลการทดสอบในไฟล์ `test-results.md`

⚠️ **กฎเหล็กของสัปดาห์นี้:** ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน — เทสต์ fail ต้องแยกให้ออกก่อนเสมอว่า **โค้ดผิด** หรือ **เทสต์เขียนผิด**

## ส่วน A — 🚀 สั่งทีเดียวจบจากสเปค (~45 นาที)

**บริบท:** สัปดาห์ที่ 6–8 สร้าง LeaveEasy ทีละขั้นมา วันนี้เริ่มจากศูนย์ใหม่ แล้วสั่งทีเดียวจบจากสเปคใบเดิม เพื่อดูว่าทำได้แค่ไหน และต้องตรวจอะไรบ้าง

### A1 — เริ่มโปรเจกต์ใหม่จากต้นแบบ (10 นาที)

**เป้าหมาย:** โคลน repo ต้นแบบมาไว้ในโฟลเดอร์ใหม่ แล้วสร้าง repo ของตัวเองบน GitHub

```
ช่วยโหลด repo https://github.com/atthawat-cha/leaveeasy-start.git ลงมาไว้ในโฟลเดอร์ใหม่ชื่อ leaveeasy-oneshot
แล้วสร้าง repo ใหม่ชื่อเดียวกันบน GitHub ของผม พร้อมส่งขึ้นไปให้ด้วย
```

**ควรเห็น:** โฟลเดอร์ `leaveeasy-oneshot` ที่มี prototype และ `leaveeasy-spec.md` + repo ใหม่บน GitHub ที่มี commit ชื่อผู้ใช้

⚠️ **repo ใบนี้คือของที่ต้องส่งเป็นใบงานที่ 4** — คนละใบกับ repo `leaveeasy` ที่ทำมา 3 สัปดาห์ ซึ่งยังเก็บไว้เหมือนเดิม ไม่ต้องแตะ

### A2 — ให้ AI เสนอทีมผู้ช่วย แล้วเราตรวจก่อน (10 นาที)

**เป้าหมาย:** ให้ Claude เสนอแผนแบ่งงานเป็นผู้ช่วย (sub-agent) หลายตัว พร้อมระบุโมเดลของแต่ละตัว **ก่อนให้ลงมือสร้างจริง**

```
อ่าน leaveeasy-spec.md แล้วเสนอว่าควรแบ่งงานให้ผู้ช่วยกี่ตัว แต่ละตัวทำอะไร
และควรใช้โมเดลไหนเพื่อไม่ให้เปลืองโทเคน ขอดูแผนก่อน อย่าเพิ่งสร้าง
```

**เช็กลิสต์ 3 ข้อที่ต้องผ่านก่อนอนุมัติแผน:**

1. งานครบทั้งหน้าจอ ข้อมูล+ล็อกอิน ปุ่ม AI — (จุดที่มักพลาด: รวบเป็นผู้ช่วยตัวเดียว)
2. งานทำตามแบบใช้โมเดลเล็ก (`haiku`) งานที่ต้องคิดใช้ตัวใหญ่ (`sonnet`) — (จุดที่มักพลาด: ให้ทุกตัวใช้โมเดลเดียวกัน)
3. มีข้อกำกับชัดเจนว่า **ห้ามทำงานนอกสเปค**

**ผลลัพธ์ที่คาดหวัง:** แผนผู้ช่วย 3 ตัวที่มี `model:` ไม่เหมือนกัน และมีไฟล์ตั้งค่าผู้ช่วยในโฟลเดอร์ `.claude/agents/`

> 💡 **ทำไมต้องระบุโมเดล:** งานทำตามแบบอย่างการสร้างหน้าจอ ใช้โมเดลเล็ก (`haiku`) ก็จบ งานที่ต้องคิดเรื่องข้อมูลกับ AI ใช้ตัวใหญ่ขึ้น (`sonnet`) — บรรทัดเดียวนี้คือค่าใช้จ่ายของคุณทั้งเดือน

### A3 — สั่งทีเดียวจบ (15 นาที)

```
ให้ผู้ช่วยทุกตัวสร้างระบบตาม leaveeasy-spec.md ให้ครบ เสร็จแต่ละส่วนให้รายงานผมทีละตัว
```

**ควรเห็น:** Claude แบ่งงานให้ผู้ช่วยทีละตัว รายงานเป็นช่วง ๆ ไฟล์ในโปรเจกต์เพิ่มขึ้นเรื่อย ๆ

**ถ้ารันเกิน 15 นาทีแล้วยังไม่จบ:** หยุดไว้แค่ส่วนที่เสร็จ แล้วไปต่อ A4 ด้วยของเท่าที่มี ส่วนที่ขาดจดไว้ทำในการบ้าน

**เรื่องคีย์:** ใช้คีย์ AI ใบเดิมของหลักสูตรเท่านั้น การย้ายคีย์ออกจากโค้ดก่อน push ทำในส่วน C ไม่ต้องรีบทำตอนนี้

### A4 — ⭐ ตรวจกับสเปคทีละข้อ แล้วสั่งแก้เฉพาะที่ขาด (10 นาที)

**ขั้นตอน:** เปิด `leaveeasy-spec.md` ไว้ครึ่งจอ เปิดเว็บที่เพิ่งได้อีกครึ่งจอ ไล่ตรวจตามตาราง

| จุดตรวจ | ที่มักไม่ตรง |
|---|---|
| หน้าจอครบตามสเปค | มักครบ |
| ชื่อช่องข้อมูลตรงสเปค | มักสะกดไม่ตรง 1–2 ช่อง |
| สถานะใช้ได้ 3 ค่าตามสเปค (`รอพิจารณา` / `อนุมัติ` / `ไม่อนุมัติ`) | มักใส่ค่าเกินมา |
| ของที่สเปคบอกว่าไม่ทำใน Module นี้ | มักแถมมา |

```
ช่องที่สะกดไม่ตรงสเปคให้แก้ตามสเปค และเอาส่วนที่สเปคบอกว่าไม่ทำใน Module นี้ออก ที่เหลือโอเค
```

**ผลลัพธ์ที่คาดหวัง:** แก้เฉพาะจุดที่บอก ไม่ได้สร้างใหม่ทั้งชุด เว็บยังเปิดได้เหมือนเดิม

⚠️ **สั่งทีเดียวไม่ได้แปลว่าคุณหายไป** — งานของคุณย้ายมาอยู่ตอนจบ ถ้าไม่ตรวจตรงนี้ คุณจะได้ระบบที่อธิบายไม่ได้

> ✅ **Checkpoint 1 (เสาร์ 13:50):** ระบบขึ้นจากสเปคในรอบเดียว · ผู้ช่วย 3 ตัวมีโมเดลไม่เหมือนกัน · ตรวจกับสเปคแล้ว
> หลักฐาน: พิมพ์ 🟢 ผ่านในแชท → สลับคนนำจอ

## ส่วน B — 🧪 เทสต์ด้วย Playwright (~35 นาที)

⚠️ **กฎเหล็กของส่วนนี้:** ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน เทสต์ fail แปลว่ามีสองอย่างที่เป็นไปได้ — โค้ดผิด หรือ เทสต์เขียนผิด แยกให้ออกก่อนแก้เสมอ

### B1 — ตั้ง 🧪 Tester แล้วยืนยันว่าเชื่อมต่อจริง (10 นาที)

**ขั้นตอน:**

1. พิมพ์ `/mcp` ในหน้าต่าง Claude Code — ต้องเห็น **playwright** ว่า **เชื่อมต่อแล้ว**
2. สั่งสร้าง sub-agent:

```
ช่วยสร้าง sub-agent ชื่อ tester ให้ผม ใช้โมเดล sonnet
หน้าที่คือใช้ Playwright MCP เปิดเบราว์เซอร์จริงแล้วทดสอบแทนคน ทดสอบตาม leaveeasy-spec.md
ห้ามแก้โค้ดของระบบเพื่อให้เทสต์ผ่าน เสร็จแล้วให้ผมอ่านไฟล์ก่อน
```

3. เปิดไฟล์ผู้ช่วย `tester` อ่านจริง ต้องมี: URL ของระบบคุณ, บัญชีทดสอบ, บรรทัด "ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน"

**ยืนยันว่าเชื่อมต่อเบราว์เซอร์จริง (ไม่ใช่แค่ตอบลอย ๆ):**

```
ช่วยเปิดเบราว์เซอร์ไปที่ <URL ของคุณ> แล้วบอกผมว่าเห็นอะไรบนหน้าจอ
```

**ควรเห็น:** หน้าต่างเบราว์เซอร์เปิดขึ้นมาเอง (ไม่ใช่ headless) และ Claude อธิบายสิ่งที่เห็นบนหน้าเว็บได้จริง

| ปัญหา | วิธีแก้ |
|---|---|
| `/mcp` ไม่ขึ้น playwright | ปิด Claude Code เปิดใหม่ ยังไม่ขึ้นให้โพสต์ถามกลาง**ทันที** อย่ารอ |
| เบราว์เซอร์ไม่เด้งแต่ Claude ตอบได้ | รันแบบ headless อยู่ สั่งว่า "ขอให้เปิดเบราว์เซอร์แบบเห็นหน้าจอด้วย" |

### B2 — เทสต์เส้นทางหลัก 2 ตัว (10 นาที)

**จังหวะที่ 1 — ขอแผนก่อน อย่าเพิ่งเขียน:**

```
ผมอยากได้เทสต์ 2 ตัว — ยื่นใบลาแล้วเห็นในรายการ กดอนุมัติแล้วสถานะเปลี่ยน
ให้ tester เสนอมาก่อนว่าจะทดสอบแต่ละตัวกี่ขั้น อย่าเพิ่งเขียน
```

**จุดตรวจแผน:** มีขั้น "รีเฟรชแล้วยังอยู่" หรือยัง? — ถ้าขาด สั่งเติมก่อนไปต่อ

**จังหวะที่ 2 — สั่งลงมือหลังแผนโอเค:**

```
แผนโอเคแล้ว เขียนแล้วรันให้ผม รายงานผลเป็นข้อ ๆ
```

**ควรเห็น:** รายงานว่าตัวไหนผ่าน ตัวไหนไม่ผ่าน และถ้าไม่ผ่านบอกว่าไปติดตรงขั้นไหน

### B3 — เทสต์กรอกไม่ครบ 1 ตัว (5 นาที)

```
เพิ่มเทสต์ กรอกฟอร์มยื่นใบลาโดยเว้นช่องหัวข้อไว้ แล้วกดบันทึก
ระบบต้องไม่บันทึกและต้องขึ้นข้อความบอก
```

**ควรเห็น:** เทสต์ผ่านเมื่อระบบปฏิเสธการบันทึกจริง

### B4 — 🔒 เทสต์ความปลอดภัย 2 ตัว ⭐ (10 นาที) — สำคัญที่สุดของสัปดาห์

⚠️ prompt นี้ยาว 4 บรรทัดโดยตั้งใจ เพราะเป็นรายการเงื่อนไขที่ **ห้ามตกข้อ** ตกข้อเดียวแปลว่าไม่ได้ทดสอบเรื่องนั้น

```
เพิ่มเทสต์ความปลอดภัย 2 ตัว
1 ไม่ล็อกอินแล้วเปิดหน้ารายการ ต้องอ่านข้อมูลไม่ได้
2 ล็อกอินด้วยบัญชีที่สอง แล้วเปิดใบลาของบัญชีแรก ต้องเปิดไม่ได้
ทั้งสองตัวถือว่าผ่านเมื่อเข้าไม่ได้
```

**ควรเห็น:** เทสต์ทั้งสองผ่าน — คือ **"เข้าไม่ได้ = ผ่าน"**

🔴 **ถ้าตัวใดตัวหนึ่งไม่ผ่าน แปลว่าข้อมูลของคุณรั่วจริง** — ให้หยุดทุกอย่างแล้วกลับไปแก้ Security Rules ก่อนทำอย่างอื่น (ดูกฎสิทธิ์ตามบทบาทในหัวข้อ 1 ของ `CLAUDE.md`)

**ปักหมุดชุดทดสอบ:**

```
ปักหมุดเก็บชุดทดสอบให้ผม
```

รวมแล้วต้องได้เทสต์ **5 ตัว**: เส้นทางหลัก 2 + กรอกไม่ครบ 1 + ความปลอดภัย 2

| ปัญหา | วิธีแก้ |
|---|---|
| เบราว์เซอร์ค้าง | ปิดหน้าต่างเบราว์เซอร์ที่ค้างทิ้ง แล้วสั่งใหม่ |
| เทสต์ fail | ถามก่อนว่า "โค้ดผิด หรือ เทสต์ผิด" ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน |
| เทสต์ความปลอดภัยไม่ผ่าน | ข้อมูลรั่วจริง หยุดทุกอย่าง กลับไปแก้กฎสิทธิ์ก่อน |

> ✅ **Checkpoint 2 (เสาร์ 14:25):** ⭐ เทสต์ 5 ตัวผ่านทั้งหมด · รวมเทสต์ความปลอดภัย
> หลักฐาน: พิมพ์ 🟢 ผ่านในแชท → สลับคนนำจอ

## ส่วน C — 📊 รายงานผล + ส่งงาน (~15 นาที)

### C1 — ให้ AI สรุปผลการทดสอบเป็นรายงาน (8 นาที)

```
ช่วยรันเทสต์ทั้งหมดอีกรอบ แล้วสรุปผลเป็นไฟล์ test-results.md ให้ผม
บอกว่าเทสต์แต่ละตัวทดสอบอะไร ผ่านหรือไม่ผ่าน และรันเมื่อไร
ข้อที่ไม่ผ่านให้บอกด้วยว่าติดตรงไหน
```

**ควรเห็น:** ไฟล์ `test-results.md` ที่โฟลเดอร์บนสุด มีรายชื่อเทสต์ 5 ตัวพร้อมผ่าน/ไม่ผ่าน และวันเวลาที่รัน
